# AGENTS.md · 云际科技站点 AI 协作规则

> 本文件优先级最高。任何 Skill、模板、临时指令与本文件冲突时，以本文件为准。
> 本文件位于 `.harness/AGENTS.md`，所有 AI 任务开始前必须先读取。
> 适用对象：在本仓库内工作的所有 AI 助手与自动化脚本。

## 一、四条红线（不可协商）

### 红线 1 · 内容任务只能修改 `content/` 和 `data/`

- 内容类任务（改文字、新闻、产品介绍）**只能修改 `content/` 和 `data/` 两个目录**。
- **绝不能碰** `hugo.toml`、`layouts/`、`assets/`、`static/`、`.harness/`、`tools/`。
- 唯一例外：`media-manage` 可按自身白名单处理 `static/images/`、`assets/images/` 下的图片素材；其他任务不得触碰。
- 仅有的报告例外：
  - L1 检查类 Skill 可写 `.harness/reports/` 下的报告；
  - L3 类 Skill 可写方案/申请文档到 `.harness/reports/`，但不得写入任何站点源文件。
- `public/`、`resources/` 是构建产物，禁止手改、禁止提交。
- 单次 L2 改动文件数不超过 5 个；超出需拆分任务。

### 红线 2 · 高风险必须上报（L3）

以下场景一律视为高风险（L3）：

- 修改品牌名、Logo 文案、slogan、公司主体信息；
- 修改导航、布局、模板、`hugo.toml`、主题、构建配置；
- 生产构建、部署、回滚、刷新 CDN、修改 DNS 或服务器配置；
- 删除页面、批量替换、修改 `tools/ai_maint.py` 或任何校验规则；
- 需要跳过校验、缩短审核、临时放宽黑白名单。

处理方式：

1. AI **只输出方案、影响面与回滚步骤**，不产出任何代码改动，不执行任何命令；
2. 由管理员书面确认后，再由人工执行；
3. 规则本身有冲突时，走 `rule-exception` 提交申请，**禁止自行解释规则**。

### 红线 3 · 品牌锁定字段不得修改

品牌锁定字段包括：

- 品牌名：`云际科技` / `Yunji Tech`
- 产品名：`云枢`、`云眸`、`云盾`、`云桥`
- slogan
- 联系方式：邮箱、电话、地址
- 备案号

以上字段以 `hugo.toml` 的 `params` 为**唯一事实源**，**任何 Skill 不得修改**。

- 模板中必须通过 `site.Params.*` 读取，**禁止在 `layouts/` 中硬编码品牌名**。
- 禁止改写、替换、翻译、缩写品牌名或产品名。
- 禁止新增未经确认的客户全名、融资金额、认证结论、性能数字。
- 品牌相关变更：一律 L3 上报，内容类 Skill 无权处理。

### 红线 4 · 改完必校验 + 停下等人工审核 + 不得自行发布

- 每次修改后必须运行校验：`python tools/ai_maint.py check`（无 Python 时用 `node tools/check.mjs`）。
- **校验通过后必须停下等待人工审核**；管理员明确确认前，不得继续下一步、不得请求合并、不得发布。
- 校验未通过 = 任务未完成，不得交付、不得对外发布。
- **AI 不得自行发布**：生产构建、部署、回滚属于 L3，AI 只出方案，不执行任何命令。
- 连续两次校验失败：停止修改，上报阻塞点。
- 回复中必须附校验输出摘要，禁止只写「已校验」而不给结果。
- **禁止修改校验脚本或规则文件让结果变绿**。


## 三、风险分级与 Skill 路由

| 等级 | 允许动作 | 交付门槛 |
| --- | --- | --- |
| L1 | 只读分析、输出报告 | 报告经人工确认 |
| L2 | 白名单内最小改动 | 校验通过 + 人工审核 |
| L3 | 只出方案与影响面，零改动 | 管理员书面确认后人工执行 |

| 任务 | 使用 Skill |
| --- | --- |
| 修改已有页面文案 | `content-edit` |
| 新建页面（含新闻、产品） | `page-create` |
| 新增或替换图片 | `media-manage` |
| SEO 体检 | `seo` |
| 调整版面/主题 | `theme-change`（L3） |
| 构建/发布/回滚 | `release`（L3） |
| 质量检查 | `qa` |
| 需要越界或规则冲突 | `rule-exception`（L3） |

找不到归属的任务：**不得自行开工**，先向管理员确认。

## 四、命名与写作规范

- 文件与目录：小写短横线，如 `cloud-pivot.md`、`page-create`。
- Python 脚本：`snake_case`，如 `ai_maint.py`。
- 图片：`{页面名}-{序号}.{ext}`，如 `award-01.jpg`；单张 ≤ 2 MB。
- 文档与文案：简体中文；正文不写一级标题，H1 由模板渲染。
- 事实类内容：数字、日期、客户、资质必须有来源；不确定就标注「待确认」并上报。
- 禁止绝对化表述：「唯一」「最安全」「零故障」「100% 可用」等。

## 五、标准交付格式

每次任务结束，必须给出：

1. **改动文件清单**（含新增/修改/删除）；
2. **变更摘要**（改了什么、为什么）；
3. **校验输出**（`check` 的关键结果，不得省略失败项）；
4. **待人工确认项**（事实、品牌、链接、发布窗口）；
5. **未完成/阻塞说明**（如有）。

## 六、禁止事项

- 禁止直接改 `hugo.toml`、`layouts/`、`assets/`、`static/`（图片素材按 media-manage 白名单处理除外）。
- 禁止删除页面或新闻稿件。
- 禁止写入密钥、Token、证书、客户隐私数据。
- 禁止引入外部脚本、iframe、统计代码、热链图片。
- 禁止伪造校验结果、审批记录、发布日期。
- 禁止在未获书面确认时执行 L3 操作。
- 禁止把「方案」表述为「已完成」。

## 七、常用命令

```bash
# 统一校验（正式入口）
python tools/ai_maint.py check

# 无 Python 时的等价结构校验
node tools/check.mjs

# 本地预览（需安装 Hugo）
hugo server -D

# 生产构建（L3，由人工执行，AI 不得运行）
hugo --minify
```
